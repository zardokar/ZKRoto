# ZKRoto 0.3.0

Frame-exact video viewer, frame capture, pose page and POV skeleton export for ComfyUI, written for the ComfyUIAssistant project (user `zardokar`). It adds no nodes and injects nothing into the ComfyUI UI: it only serves its own page and three small routes.

- Page: `http://127.0.0.1:8188/zkroto/` (optional query: `?video=<name in input\>&frame=<n>&fps=30000/1001`)
- Library files: `/zkroto_lib/` (= `third-party/`, MediaPipe under `third-party/mediapipe/`)
- Version check: `/zkroto/version` (the Python side; it changes only after a ComfyUI restart)
- Export routes (0.2): `POST /zkroto/export`, `GET /zkroto/shot`, `GET /zkroto/sheetdata` - write / read only under `input\ZKRoto\<shot>_<character>\` (rules: `zk_export.py`); they exist only after a ComfyUI restart
- Script API for Claude through the browser pane: `window.zk`, see [docs/zk_api.js.md](docs/zk_api.js.md)

## Rules for any AI working here
- Code follows **AppMaker v003** (`app-maker-v003`, from 0.1.2): files <=200 lines split by category, no one-line functions, one statement per line, comments <=3 lines (overflow to `docs/<file>.md`), settings at the top of every file, every text in `web/constants/zkroto.json`, every tunable in `web/config/zkroto.json`, logical (pure) and component code in separate files, the pose engine behind the facade `web/js/zk_pose.js`.
- Every trial (settings, data source, results joint by joint on a 20 x 30 grid, PASS / FAIL, what was seen) is recorded in **`atdd/trials.json`** - one file, nothing listed elsewhere (user, voice 2026-11-09 22:0x). Run and record: `node dev/zk_trial.js --id T.. --title "..." --params '{...}' --why "..." --record`; grid logic `dev/zk_grid.js`.
- Every change or run is checked by **values AND the reference pictures**, looked at closely (zoomed on the head) before anything is sent; values that pass with a picture that looks wrong = FAIL (user, voice 2026-11-09 21:3x: "เช็คทั้ง value และภาพ reference ตลอดทุกครั้ง ไม่งั้นก็พังอยู่ดี"). Measure the face against the face (% of face width), the head against the head, not only % of the image height.
- Every test of the pose, POV or face layer is checked on **both views, front and side**: ZKRoto's POV of the FRA-007 `front.png` pose at yaw 0 and at the `side.png` angle, each fitted onto MediaPipe's own result on ComfyUIAssistant `.dropzone/Char_FRA-007/front.png` / `side.png`, shown as one picture with the error in % of the height (user, voice 2026-11-09 21:1x: "ไม่ว่าจะเป็นหน้าหรือข้างอ่ะ ใช้ front side ตลอด"). Tools: ComfyUIAssistant `.dropzone/zkroto/20261109_2114_front_side_check/` (`compare_fs.mjs` + `draw_fs.py`).
- From 0.2 the page is **re-skinnable** (user, 2026-11-09: layout, components and style must be easy to swap): logic modules know nothing of the DOM; each component lives in `web/components/<name>/` with its own JS and CSS and talks to others only through the event bus / facades; every colour and size is a CSS variable in `web/theme/zk_theme.css`; where components sit is decided only in `config.layout` (+ the page slots). `atdd/zk_layout.test.js` checks these rules. How-to: [docs/zk_api.js.md](docs/zk_api.js.md).
- Order for every change: analyse -> design -> unit tests first (seen RED) -> code -> `atdd\all_test.bat` + `batch\check_style.bat` both PASS -> before / after check in the real ComfyUI -> review.
- Only pose / joints are taken from a clip, never a real person's face, identity or distinctive marks. Characters made from it are original adults.
- No automatic install, download or spend. Claude does not run git, npm or `.bat` files on the user's machine; the user commits and pushes.
- Two copies (user, 2026-11-07, Q6 = a): this repo is the source of record; the same files are written to `E:\ComfyUI\ComfyUI\custom_nodes\ZKRoto\` and byte-compared after each change.
- Third-party binaries are not in git (Q7): see [third-party/NOTICE.md](third-party/NOTICE.md).

## What it does
- Loads an mp4 from ComfyUI `input\` (name, or `subfolder/name`) or a local file (picker or drag and drop).
- **Character sheet** (0.2.5, user choice B 2026-11-10): a still (png / jpg / webp) loads as a one-frame clip. If its file name has the word `front` and the same name with `side` exists in the same `input\` folder (`front.png` + `side.png`, `FRA007_Front.png` + `FRA007_Side.png`), the side picture is posed once and POV takes its depth from it (**x / y from: front + side pictures**; `web/js/zk_sheet.js`). A dropped or picked local file cannot see its folder, so load sheets by name. Best match with the drawings at distance 5 m (trial T14).
- Steps frame by frame (buttons, slider, arrow keys, Shift = 10 frames). Default 29.97 fps (`30000/1001`); other rates in the fps list.
- Seeks to the middle of frame n and confirms the frame shown with `requestVideoFrameCallback`.
- **Capture (C)** saves the shown frame as PNG through ComfyUI's `/upload/image` to `input\ZKRoto\capture\<video>\<video>_f000123.png` (overwrites the same frame; own `capture` folder from 0.2).
- **Pose (P)** runs MediaPipe Pose Landmarker on the shown frame (up to 2 people): 33 image and 33 world landmarks, drawn as an overlay, kept in `zk.lastPose`.
- **People** (0.2): person 1 (blue) / 2 (orange) buttons choose whose pose POV and Export use; **Swap** exchanges them in this frame (recorded).
- **Views** (0.2, key V): Source | POV | Split. POV = a camera placed around the 3D pose (yaw, eye height above the floor, distance, FOV, roll, look at hips / chest / head; presets Front / Back / Left / Right / Top; orbit with the mouse), output 832 x 1216 Portrait / Landscape or Custom (x64), `fit` on the margins (top 10 %, bottom 9 %, sides 5 %, provisional) or `true camera`; layers OpenPose 18 / MediaPipe 33; joints under visibility 0.30 hidden. Points tab = the 33 points as a table; top view of person, source camera and POV eye.
- **Face** (0.2.1, design 1.12): with `third-party\mediapipe\models\face_landmarker.task` present, Pose (P) also runs MediaPipe Face Landmarker on a head crop of each person (478 points); POV places the mesh on the head (its own shape, torso scale) and hides the points that face away from the eye; layer **Face** on screen. Export adds `openpose\face\src|pov\` (OpenPose face 70: PNG + JSON) and `mediapipe\face\src|pov\` (478 points + world). Without the model: body only.
- **Full** (0.2.8, design 1.13 F1, user choice A): Export also writes `openpose\full\src|pov\` = one PNG per camera with body 18 and face 70 drawn on one black canvas (the same pixels as the `openpose\` body PNG with the `openpose\face\` points on top, like the annotator's `openpose_full`), same file name as the body PNG, for a single ControlNet openpose input. PNG only (the JSON stays per layer). No face for the person: the body PNG alone, so every exported frame has a full PNG.
- **Export range** (0.2.9, user 2026-11-10: every frame is generated, then traced as vector paths): fields **from** / **to** next to Export (empty = the whole clip) and the button **Export range** (Stop while it runs); `zk.exportRange({from, to, src})`, `zk.stopRange()`. Pass 1 poses every frame; one **fit** framing is computed from the POV joints of all frames together, so the character keeps one scale and place over the range (a per-frame fit would rescale it a few % from frame to frame); pass 2 exports each frame with it and writes `fit: {s, tx, ty}` and `range: [from, to]` into the POV camera of each `zkroto\` frame JSON. Sheets are rebuilt once at the end. Frames without the chosen person are skipped and listed. The screen preview still fits each frame on its own.
- **Point editing** (0.3.0, user 2026-11-10: edit in the Source view, one frame at a time, edits kept apart): **Edit (E)** turns it on; drag a MediaPipe point of the chosen person to where the joint really is, **Alt+click** puts it back to MediaPipe, **Reset frame** clears the shown frame. Only moved points are stored, image coordinates 0..1, in `zkroto\<shot>_<character>_edits.json` (written at each drop through the export route, read once per shot folder; a file of another clip is not used). Every pose of that frame gets them (overlay, POV, Export, Export range); the MediaPipe pose stays as `raw`. The POV follows in every x / y mode: image x / y replaced, world x / y moved by the same pixels in metres (torso scale), depth unchanged. The zkroto frame JSON lists the edited points (`edited`). Swap keeps edits with the person as shown. API `zk.editMode(on)`, `zk.movePoint(i, x, y)` (video pixels), `zk.resetPoint(i)`, `zk.resetFrame()`, `zk.edits()`. The face mesh does not follow edited head points.
- **Guides for the vector step** (`tools\zk_guides.py`, 2026-11-10, updated 2026-11-11, no change to the page): one SVG per exported frame of a shot, same size as the frame, with locked Inkscape layers: `generated` (optional, the generated picture of that frame), `mediapipe 33 bones`, `openpose 18` (bones + joints, hidden by default since 2026-11-11: its neck -> hip V is not the body), `body axes` (shoulder line 11-12, hip line 23-24 and the spine between their midpoints, ids `axis_shoulders` / `axis_hips` / `axis_spine` / `axis_shoulder_mid` / `axis_hip_mid`, light dashes over a dark outline; a line is left out when one of its points is under `--min-vis`), `joints` (every visible MediaPipe joint at its exact pixel, ids like `mp_15_left_wrist`, name as tooltip), `face 70` (when the frame has a face file), `low visibility` (MediaPipe points under `--min-vis`, hidden) and `info` (frame, camera, range framing). Run `python tools\zk_guides.py <shot folder> [--camera NAME|src] [--images DIR] [--min-vis 0.3] [--out DIR]`; default output `<shot>\guides\<camera>\`. Pictures: `--images DIR`, or by default `<shot>\gen\<camera>\` when it exists (`--images ""` for none). When every picture name has a frame number (`_f000012_`) they are matched by number and a frame without a picture just has no `generated` layer (the run names them); otherwise they are matched in name order and the counts must be equal. Linked with a relative `xlink:href`. **Naming the generated pictures** (`tools\zk_genname.py`, 2026-11-11): `python tools\zk_genname.py <shot folder> <ComfyUI output folder> --prefix <SaveImage prefix> [--camera NAME|src] [--last] [--force]` copies (never moves) the pictures in counter order to `<shot>\gen\<camera>\<frame file name>_gen.png` and writes `gen_map.txt` (source -> copy). The number of pictures must equal the number of exported frames; with more (earlier runs in the same folder) `--last` takes the newest; a different picture already in `gen\` is not replaced without `--force`; on any error nothing is copied. Example for workflow v001: `python tools\zk_genname.py E:\ComfyUI\ComfyUI\input\ZKRoto\<SHOT> E:\ComfyUI\ComfyUI\output\FRA-007 --prefix zkroto_pose_v001a1_hands --last`, then `python tools\zk_guides.py E:\ComfyUI\ComfyUI\input\ZKRoto\<SHOT>`. Both: Python 3 standard library only (`tools\zk_shotfiles.py` is shared); joint names, colours and limbs are read from `web\`.
- **Export (Ctrl+E)** (0.2): MediaPipe 33 is the master data (JSON); OpenPose 18 is computed from it (PNG + JSON for ControlNet); one MediaPipe sheet image per shot and camera; our record per frame + a shot index. Folder `input\ZKRoto\<shot>_<character>\` (see docs/zk_api.js.md). "source camera" box (on by default) adds the clip's own angle.

## Browser
The page loads its JSON with import attributes (`with { type: "json" }`): Chromium 123+ (Chrome, Edge, the Claude desktop browser pane), Safari 17.2+, Firefox 138+. Older browsers show a blank page.

## If the page stays blank
`web/config/zkroto.json` and `web/constants/zkroto.json` are loaded as JSON modules together with the scripts. A missing file or a JSON typo stops the whole page; the browser console (F12) names the file. Check both with any JSON validator.

## Version bump
One version in five places, checked by `atdd/zk_version.test.js`: `web/constants/zkroto.json` `version`, `__init__.py` `VERSION` (shows at `/zkroto/version` only after a ComfyUI restart), the entry `js/zk_main.js?v=` and every value of the import map in `web/index.html`, and the title of this README. A new page module needs an import-map line (the test fails without it).
